Configuration guide

The most important configuration idea in this repo is responsibility: model structure belongs in the detector spec, runtime behavior belongs in the pipeline, and only advanced overrides should reach into raw MMDetection dictionaries.

DetectorSpec

Use a detector spec when you want to express intent instead of wiring every MMDetection field manually. It is the recommended surface for new experiments. 

from simpledet.suite import build_decoder, build_detector, build_neck

spec = build_detector(
    "deformable_detr",
    encoder="convnext_tiny.in12k_ft_in1k",
    neck=build_neck(name="ChannelMapper", out_channels=192, num_outs=4),
    decoder=build_decoder(embed_dims=192, num_queries=300),
    num_classes=5,
    in_channels=3,
)

In this example, architecture and num_classes describe the task, encoder describes the backbone source, neck adapts features across scales, and decoder is only needed because the detector family is transformer-based.

Compile to a model dictionary

from simpledet.suite import compile_detector_spec
model_cfg = compile_detector_spec(spec)

The compiler fills model sections such as backbone, neck, bbox_head, roi_head, encoder, and decoder.

Compile when you need to inspect or override the exact MMDetection-style model definition. In most user flows you do not need to edit this dictionary directly after compilation.

Custom backbones

from simpledet.suite import EncoderSpec

custom_encoder = EncoderSpec(
    source="config",
    name="custom-backbone",
    backbone_cfg={"type": "MyBackbone", "depth": 18},
    feature_channels=(64, 128, 256, 512),
)

Use this path when the backbone is not coming from timm.

Runtime config

ObjectDetectionPipeline still loads simpledet/simpledet/src/base_config.py and replaces cfg.model with the compiled detector definition. Dataloaders, evaluators, schedulers, and hooks continue to live in the runtime config.

Put it in the detector spec

Architecture, backbone, neck, head, decoder, feature interfaces, class count.

Put it in the pipeline

Dataset paths, image size, batch size, optimizer settings, checkpoints, logging, evaluators.

Use raw overrides sparingly

Only when the public builders do not yet expose a field you genuinely need to change.
