Core concepts

What to understand before editing training scripts, adding datasets, or swapping detector backbones.

Quick map: Architecture Execution paths Configuration model Artifacts and outputs

Architecture overview

  • simpledet package: core Python modules under simpledet/ expose CLI, training, inference, and utilities.
  • Detector backends: scripts and presets in simpledet/detectors and many model blueprints in simpledet/src.
  • Configuration-centric: model behavior is primarily driven by config objects and run scripts.
simpledet/
  cli.py
  __main__.py
  api.py
  detectors/
    train.py
    infer.py
    evaluate.py
  src/
    configs/
  simpledet/pyscripts/
  runscripts/

Execution paths

CLI-first flow

Use entrypoint python -m simpledet or installed command simpledet for fast experiments and checks.

simpledet --check-openmmlab

Script-first flow

Use repo scripts for dataset-specific launch presets and repeatable runs.

python runscripts/SenTrainer.py ...
python runscripts/VenTrainer.py ...

API-first flow

Use simpledet.train() for programmatic integration in notebooks or services.

from simpledet import train
result = train(config={...})

Configuration model

Most experiment control comes from explicit parameters: datasets, model family, optimizers, run length, batch sizes, seeds, and sensor options.

config = {
  "dataset": "path/to/annotations.json",
  "dataset_path": "path/to/dataset_root",
  "model_name": "faster_rcnn_resnet50_fpn",
  "epochs": 1,
  "batch_size": 2,
  "train_split": "train",
  "device": "cuda",
}

Artifacts and expected outputs

  • Checkpoint files (.pth) in the selected output folder.
  • Metric reports like coco_metrics.json for post-run validation.
  • Log and scalar files useful for iteration comparison and debugging.
ls -R runs/mmdet_smoke
python -c "import json;print(json.load(open('runs/mmdet_smoke/coco_metrics.json')).keys())"
